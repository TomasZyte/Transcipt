# Poslovnica — Telegram-бот транскрибации

Python 3.12, aiogram 3, SQLite. Файлы отправляются через S3/R2 в RunPod;
ссылки скачивает воркер через yt-dlp. Результат содержит расшифровку, спикеров,
тайм-коды и конспект. Доступны инструменты по тексту, Q&A, перевод и TXT/SRT/Markdown.

## Возможности и ограничения

- Голосовые, аудио, видео, кружки и документы с MIME audio/video; ссылки.
- Тарифы free/start/pro, расход минут по календарному месяцу UTC, ограничение
  длительности отдельного файла. Продление подписки не сбрасывает расход.
- Один активный файл или ссылка на пользователя; другие пользователи работают параллельно.
  Защита рассчитана на **один polling-процесс** и не является распределённой очередью.
- Экспорт, AI-инструменты и Q&A доступны владельцу сохранённого задания.
- ЮKassa и Stars: проверка счёта, атомарная запись платежа и выдача тарифа,
  защита от повторного `charge_id`. Чек отмечается отправленным после доставки.
- Промокоды, глоссарий, режим обслуживания, статистика, CSV-экспорт, админские команды.
- Локальный Bot API позволяет работать с большими файлами. Локальная копия удаляется
  после загрузки в хранилище. Удаление объектов R2 кодом не реализовано; срок presigned URL
  не удаляет объект. Lifecycle бакета и фактический срок хранения нужно проверить отдельно.
- Клиент RunPod ограничивает всю операцию 3600 секундами, включая HTTP-запросы.
  Локальный таймаут не отменяет удалённое задание. Восстановления после рестарта пока нет.

## Локальные тесты

Установить Python 3.12 и зависимости в отдельное окружение. Команды для текущей копии
репозитория, каждая — отдельная строка PowerShell:

```powershell
py -3.12 -m venv C:\Users\Projects\Transcipt-git\.venv
& 'C:\Users\Projects\Transcipt-git\.venv\Scripts\python.exe' -m pip install -r 'C:\Users\Projects\Transcipt-git\tg-bot\requirements.txt'
& 'C:\Users\Projects\Transcipt-git\.venv\Scripts\python.exe' -m unittest discover -s 'C:\Users\Projects\Transcipt-git\tg-bot\tests' -v
```

Тесты не читают `.env`, не запускают polling и не вызывают Telegram/R2/RunPod.
Они используют временные SQLite-файлы и подменяют внешние вызовы.
На Windows `asyncio` требует внутренний loopback-сокет даже для таких тестов.

## Настройка отдельного тестового экземпляра

Использовать отдельную точку входа `integration_test.py`, явный `.env.integration-test`
по [integration.env.example](integration.env.example) и отдельные бот/R2/RunPod.
Она разрешает один личный Telegram ID и одно выбранное сообщение до 60 с/10 МиБ,
отключает платежи, ссылки и AI-кнопки, ведёт журнал отправок и пытается отменить
облачное задание при ошибке/таймауте. БД и результаты находятся в `.test-runtime/`.
Инструкция запуска, ограничения бюджета и результаты двух прежних живых проверок:
[INTEGRATION-TEST.md](INTEGRATION-TEST.md). Новый runner проверен офлайн.

В обычном запуске `bot.py` используются `.env`/переменные окружения;
`DB_PATH` по умолчанию относителен рабочей папке. `LOCAL_BOT_API` пустой — облачный
Telegram API; иначе задаётся адрес своего Bot API. `TG_TIMEOUT` — таймаут запросов
Bot API в секундах. В production запуском управляет служба `PoslovnicaBot`.
Не запускать второй polling с рабочим токеном. Перед push учитывать также
автосборку **тестового** endpoint, привязанного к ветке PR.

## Администрирование

`ADMINS` — список Telegram user id через запятую. Команды: `/stats`, `/export`,
`/pending`, `/receipt ID URL`, `/newpromo CODE PLAN MONTHS USES`, `/maintenance on|off`,
`/broadcast`, `/refundstars USER_ID CHARGE_ID`, `/evaltask TASK COUNT`.
`MONTHS=0` означает бессрочный промокод, `USES=-1` — неограниченные активации.
Возврат Stars пока не пересчитывает тариф автоматически; это требует ручной сверки.

Воркер находится в `transcribe-backend/worker` и уже поддерживает `analyze`.
Его код, модели и промпты в этом PR не менялись. Для изменения промптов сначала
снять baseline через `/evaltask` по правилам [AGENT-HANDOFF.md](../AGENT-HANDOFF.md).
