## 01.11: CTC ограничен исходным участком речи — проверено на GPU

`channel-speech-v1` сохраняет модели WhisperX, ASR-контекст и автоматический
выбор дефектов из предыдущего варианта. Native-фраза должна пересекать
ровно один исходный VAD-участок; иначе её принадлежность остаётся спорной.
CTC получает полный исходный речевой участок, а не контекстное окно и не
подрезанные готовые тайм-коды. Текст не делится между несколькими окнами
по догадке. Соседняя распознанная реплика не заменяет пропущенную речь.

Для каждого затронутого участка есть `review_spans`: гипотеза, причины
сомнений либо `unresolved_speech`. При пропуске исходные raw/CTC сохраняются
для аудита, итоговый экспорт блокируется. Native-ошибки и расхождение
слов сохраняются даже при корректных новых временах CTC. Human quality
и release_ready остаются false. Рабочий handler и обычный Dockerfile
не меняются; профиль доступен только с тестовыми флагами.

## Новый тест: непрерывные речевые участки (31.10)

`channel-runs-v1` / `channel_runs.py` сохраняет те же WhisperX 3.8.6,
large-v3, русский aligner и публичный VAD. В каждом канале VAD выделяет
речь; соединяются только разрывы меньше 0,4 с, добавляется контекст 0,12 с
без перекрытия соседних окон. Длинная непрерывная речь ограничена 30 с;
в evidence явно отмечаются такие разрезы. Паузы не вырезаются из временной
шкалы. Нет подсказок словами, числом собеседников или ручными временами.

WhisperX распознаёт окна батчами, не объединяя удалённые реплики.

времена переводятся в глобальные один раз. Сохраняются исходные VAD,
план окон, ASR и alignment; клиент воспроизводит экспорт. Выход времени
за локальное окно, пропуск слова/текста или слово >2 с блокируют кандидат.
Пустой канал остаётся ошибкой качества. Автоматический pass не означает
принятого человеком качества. Gated-диаризация и LLM не вызываются.
